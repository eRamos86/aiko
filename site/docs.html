aiko docs

Everything Aiko speaks — config, commands, slash commands, and the daemon.

config (~/.aiko/config.yaml)

brains:
  - name: my-brain
    type: openai            # or: ollama
    model: nvidia/nemotron-3-super-120b-a12b
    base_url: https://integrate.api.nvidia.com/v1
    api_key: ${NIM_API_KEY}     # $ENV expansion supported

servers:                     # list — local:, server_one:, server_two: …
  - name: server_one
    url: https://aikod.example.com
    auth: nova_jwt           # or: token
    identifier: you@mail.com

agents:                      # local CLI agents she can spawn
  - name: hermes
    command: hermes
    one_shot: [chat, -q, "{{prompt}}"]

context_providers:           # docs attached to dispatches
  - name: my-vault
    type: http_docs
    base_url: https://vault.example.com
    headers: {X-Vault-Secret: ${VAULT_TOKEN}}
    lazy_attach: [Agents/Context Router.md]

mcp_servers:                 # Aiko's own MCP client
  vault:
    url: https://vault-mcp.example.com/mcp
    headers: {X-Vault-Secret: ${VAULT_TOKEN}}

the daemon (aikod)

Run on a server to accept dispatches from your local Aiko. It exposes sessions, transcripts, steer messages, health. Auth: Nova JWT or bearer token. The repo ships a systemd unit (aikod.service).

status tab & /status

Brains, servers, agents, MCP servers, session counts — all in one glance. Runs every 5s while the status tab is active.

philosophy

  • local-first: your config, your keys, your machines. No cloud required — any OpenAI-compatible endpoint works.
  • lazy context: inject indexes, not libraries. Aiko reads a small router doc; deeper docs get fetched on demand.
  • competence first, catgirl always: she gets work done, then purrs about it.
